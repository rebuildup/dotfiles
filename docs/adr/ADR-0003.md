# ADR-0003: SOPS + age as the portable secret bootstrap boundary

- Status: Superseded
- Date: 2026-09-23
- Classification: Project-local Operating Policy / Practice
- Extends: ADR-0001, ADR-0002
- Superseded by: ADR-0004

## Context

This decision originally selected SOPS + age so encrypted portable secrets could live in Git while one external age identity acted as the bootstrap root.

That model worked for encrypted-file portability, but the actual development environment needs a stronger secrets-management boundary: centralized access control, auditability, machine identities, environment/path scoping, rotation, and clean separation between human and automated access.

## Historical decision

SOPS + age was briefly used as the canonical store for portable secret material. Encrypted payloads were committed and runtime values were injected with `sops exec-env`.

## Supersession

ADR-0004 replaces this model with Infisical.

After migration:

- SOPS-encrypted payloads are not active repository state.
- `.sops.yaml` is not an active configuration surface.
- age private identities are not part of the machine bootstrap contract.
- secret value changes do not create Git commits.
- Git contains only non-secret Infisical project binding/configuration when required.

The historical encrypted payload remains reachable through Git history until repository history is intentionally rewritten. Secrets migrated out of it SHOULD be rotated when practical so future compromise of the former age identity cannot expose still-valid credentials.
