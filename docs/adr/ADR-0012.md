# ADR-0012: Require measured harness-specific quality for free agent selection

- Status: Accepted for implementation; model qualification requires evidence
- Date: 2026-10-24
- Related: ADR-0009, Issue #72, PR #73

## Context

The live catalog proves price and advertised capability, not autonomous
development quality. The first configured model previously won without any
coding evidence. Earlier one-file smoke tests cannot support this stronger
claim. Free request quotas are shared across models and failed requests count.

## Decision

Keep the existing availability gate and add a separate quality gate keyed by
exact model ID and harness. Versioned, fresh, repeated externally graded trials
are required. Public benchmark scores retain their source and conditions and
are never added into a cross-benchmark score. Compare completion reliability
first, tool reliability second, speed last. Context and TOML preferences cannot
compensate for failed development tasks.

An empty or uncalibrated evidence store qualifies nothing. A baseline must be
chosen from actual repeated evaluations; qualification thresholds derive from
that baseline. Three capability trials are a conservative repeatability floor,
not proof of broad reliability. Fourteen-day freshness is an operational safety
ceiling for volatile free offerings, not a measured model characteristic.
Unknown, stale, mismatched or malformed evidence fails closed. Explicit free
model use without sufficient quality evidence requires `--allow-unverified`.
The random free router cannot represent a stable evaluated model and is excluded.

Evaluation code runs only on explicit request. Each trial uses a new disposable
project with public tests and an independent grader outside the child workspace.
The grader checks behavior and protected-file integrity; self-reported success
is irrelevant. Process isolation is not a malicious-code sandbox and this small
suite does not prove general coding capability.

To enforce an actual HTTP request budget across native clients, the evaluator
may run a process-local loopback forwarding guard. It pins the exact free model,
counts failed attempts, stops on quota/auth failures and keeps the real key in
the evaluator parent. This guard is necessary evaluation instrumentation; it is
never a normal-launch proxy, installed service, alternate provider or fallback.
The normal launcher stays thin and starts one native harness.

## Limits and reevaluation

Catalog caches establish pricing only as of their fetch time. Failed refreshes
remain useful for discovery, but stale entries cannot authorize execution.
No paid API, automatic model retry or quota failover is introduced. Real API
failures remain distinct from capability failures. If quota prevents comparison,
record the blocker and leave the quality gate closed. Review this design when
clients offer a native enforceable total request cap or evidence shows the
fixture does not distinguish useful coding ability.
