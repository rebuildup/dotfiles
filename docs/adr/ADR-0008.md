# ADR-0008: Keep Claude common configuration provider-neutral; isolate MiniMax as a transitional / legacy provider

- Status: Accepted
- Date: 2026-09-23
- Classification: Architecture / Practice
- Extends: ADR-0004, ADR-0006, ADR-0007
- Supersedes: None

## Context

`rebuildup/dotfiles` provisions shell, editor, and agent configuration across macOS, Linux, and WSL. Claude Code is one of the supported agents; Codex and OpenCode sit alongside it through `agents/<provider>` submodules.

Provider migrations have happened before and will happen again. The next intended migration target is `MiMo`, with `MiniMax` planned to be retired soon. Until that retirement, the workspace still depends on `MiniMax` for at least one active Claude path.

Pre-ADR evidence on this machine (2026-09-23) shows the Claude common layer is currently coupled to `MiniMax`:

- `~/.bashrc` exports Claude-Code-shaped env vars (`ANTHROPIC_BASE_URL`, `ANTHROPIC_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL`, `ANTHROPIC_DEFAULT_{SONNET,OPUS,HAIKU}_MODEL`, `API_TIMEOUT_MS`, `CLAUDE_CODE_*`) at login-shell scope. Changing provider requires editing the global init file.
- The self-hosted Infisical instance at `https://secrets.rebuildup.dev` (`dotfiles` project `d4c2fc09-a923-4a38-9cf4-b51769aadb76`, environment `dev`) holds `MINIMAX_TOKEN_PLAN_KEY` and an `ANTHROPIC_AUTH_TOKEN` alias whose value is a verbatim copy of the legacy MiniMax credential.
- `~/.claude/settings.json` (drifted from the `agents/claude` baseline) embeds the MiniMax URL, MiniMax model names, MiniMax-specific timeouts, and a `modelOverrides` map keyed by MiniMax model id.
- The cross-platform `agents/claude` submodule baseline contains a `C:/Program Files/nodejs/node.exe C:/Users/...` absolute Windows path in its `SessionStart` hook, on top of the MiniMax coupling.

These couplings make the current `dotfiles` setup unable to add `MiMo` (or any other provider) without rewriting the common layer, and they make the legacy MiniMax key indistinguishable from a real Claude canonical credential.

## Decision

1. **Provider-neutral common layer.** The Claude common configuration delivered by `dotfiles` and `agents/claude` MUST be provider-neutral. It MUST NOT bake a specific AI provider's URL, model name, credential name, or compatibility flag into settings.json, `.bashrc`, or any other file that the bootstrap symlinks into `$HOME`.
2. **`ANTHROPIC_*` env names are not `MiniMax` aliases.** The `ANTHROPIC_*` env names that Claude Code consumes MAY be set as fall-through names for whatever credential the active provider supplies, but `dotfiles` MUST NOT define, ship, or generate an `ANTHROPIC_AUTH_TOKEN` (or any `ANTHROPIC_*`) value by copying from a `MINIMAX_*` secret. If a provider needs an Anthropic-shaped alias, that alias MUST be produced by the provider-specific layer, not the common layer.
3. **Provider-specific runtime layer.** Provider-specific runtime state lives under a per-provider boundary. The bootstrap keeps that boundary as process-scoped `with-secrets`/wrapper injection (see ADR-0004 §"Human workstation flow" and ADR-0006 §"Bootstrap"). `MiniMax`, `MiMo`, and any future provider each get their own entrypoint, each only loaded when invoked. Login shell MUST NOT globally export provider URL / model / compatibility flags.
4. **`MiniMax` is transitional.** `MiniMax` is treated as a transitional / legacy provider. Active MiniMax paths MUST keep working until retirement, but new work MUST NOT extend the MiniMax coupling. No new canonical alias MAY be created for MiniMax's sake; the existing `MINIMAX_TOKEN_PLAN_KEY` may remain as a legacy secret until retirement.
5. **`MiMo` adoption surface.** Adopting `MiMo` MUST require only adding a provider-specific entrypoint under `agents/<provider>` or the equivalent location. Adopting `MiMo` MUST NOT require edits to `home/`, `home/.config/`, or the global `~/.bashrc` baseline. The provider-neutral guarantee from decision 1 is what makes that path possible.
6. **`agents/claude` baseline portability.** The `agents/claude` submodule baseline MUST NOT contain provider URL / model / `MiniMax`-specific env, and MUST NOT ship machine-specific absolute paths (Windows or Unix) as canonical Claude state. Platform-specific bindings (e.g. `SessionStart` hook command) belong in a platform adapter layer owned by the host repo (`dotfiles`), not the cross-platform submodule.
7. **Windows host fixes stay host-side.** Any fix that only matters on Windows (or only matters on WSL/Linux) MUST live in `dotfiles` and travel with `home/`, never as a committed path inside `agents/claude`. `agents/claude` MAY provide a portable *example* hook shape; it MUST NOT commit a concrete absolute path.

### Target structure

```text
Claude common config (dotfiles + agents/claude baseline)
  └─ provider-neutral

Provider-specific runtime
  ├─ minimax   # transitional / legacy
  ├─ mimo      # future
  └─ anthropic # only if a separate path is justified

Infisical (self-hosted)
  ├─ provider-specific credentials
  └─ common config MUST NOT point at any provider directly
```

### Migration map for existing MiniMax coupling

| Surface | Current state | Required direction |
| --- | --- | --- |
| `~/.bashrc` global export of `ANTHROPIC_BASE_URL` / `ANTHROPIC_MODEL` / `ANTHROPIC_DEFAULT_*_MODEL` / `API_TIMEOUT_MS` / `CLAUDE_CODE_*` | Set globally at login shell | Move to a per-provider wrapper invoked via the existing `script/with-secrets` family |
| `~/.claude/settings.json` `env.*` and `modelOverrides` | MiniMax hardcoded | Provider entrypoint injects them at process start; settings.json no longer carries provider URL/model |
| `agents/claude/settings.json` | Windows absolute path in baseline, missing provider-neutral entries from the user-side drift | Remove the absolute Windows path; add a portable example; do not introduce MiniMax state |
| `MINIMAX_TOKEN_PLAN_KEY` (Infisical) | Already canonical | Stay as legacy; no new aliases |
| `ANTHROPIC_AUTH_TOKEN` (Infisical, alias) | Plain MiniMax copy | Alias gets retired once the provider entrypoint stops needing it (see `rebuildup/dotfiles#30`) |

## Consequences

- Provider migrations stop requiring edits to common bootstrap files; only the new provider entrypoint needs to be added.
- Active `MiniMax` workflows continue to work as long as their provider entrypoint exists. Their surface is now visibly a transitional layer, not the implicit default.
- `agents/claude` becomes usable as a `dotfiles` submodule candidate without dragging Windows path or MiniMax coupling into machines that never used MiniMax.
- The Infisical `ANTHROPIC_AUTH_TOKEN` alias loses its current CoT (it's a MiniMax copy) and should be retired once the wrapper layer is in place. Until then, removing it would break the current MiniMax Claude Code path.
- Login shells stop carrying `ANTHROPIC_*` and `CLAUDE_CODE_*` MiniMax-shaped values; ad-hoc `claude` invocations no longer accidentally hit the MiniMax endpoint. Users invoke `with-secrets claude ...` or a provider-specific wrapper.

## Re-evaluation triggers

Reconsider this decision if any of the following becomes true.

- A new provider enters the workspace whose boundary cannot be expressed as a process-scoped wrapper (for example, a provider that requires a host-side daemon or system-level install).
- The retirement of `MiniMax` lands and the legacy secret / wrapper can be removed; at that point the alias retirement tracked by `rebuildup/dotfiles#30` should land in the same release as the wrapper removal.
- The `agents/claude` submodule baseline acquires an officially supported platform-adapter mechanism that is provider-neutral and portable; until then, host-side platform adapters are accepted in `dotfiles` without committing them to the submodule.
