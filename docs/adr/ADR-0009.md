# ADR-0009: Activate the Claude submodule through a symlinked `home/` entry and machine-local `settings.local.json`

- Status: Accepted
- Date: 2026-10-07
- Classification: Architecture / Practice
- Extends: ADR-0005, ADR-0008
- Supersedes: None

## Context

ADR-0005 pins Claude Code global configuration as the `agents/claude` submodule, but it deferred activation until the child repository was portable enough that the same `dotfiles` commit would behave identically on every operating system.

Two things changed:

- The `agents/claude` baseline became portable and provider-neutral per ADR-0008 decision 6: it carries no provider URL or model, and no machine-specific absolute path.
- Machine state that cannot be portable accumulated outside the submodule anyway. The Herdr `SessionStart` hook is installed and rewritten by Herdr itself on each machine, and its command line necessarily names a machine-local path.

Meanwhile `~/.claude/settings.json` on this machine had drifted into an unmanaged local file holding exactly that Herdr hook, so the submodule baseline and the effective live configuration were two unrelated things.

`script/link` also only traversed regular files under `home/`, so a symlink entry pointing into a submodule would have been silently ignored.

## Decision

1. **The Claude submodule is active.** `home/.claude/settings.json` is a tracked symlink to `../../agents/claude/settings.json`, and `script/link` publishes it at `~/.claude/settings.json`. Claude Code global configuration therefore has exactly one tracked source of truth.
2. **`home/` entries may be symlinks.** `script/link` and `script/check` traverse both regular files and symlinks under `home/`. Linking stays idempotent and non-destructive: a managed target that is a symlink to something else is still a conflict.
3. **Machine-specific values use `settings.local.json`.** Values that cannot be portable — the Herdr `SessionStart` hook — live in the untracked `~/.claude/settings.local.json`, which Claude Code merges over the managed baseline. This is the host-side platform adapter that ADR-0008 decisions 6 and 7 already required, expressed in Claude Code's own native override file rather than a second tracked file.
4. **The submodule stays free of machine bindings.** Adding a new machine-local hook means adding a line to that machine's `settings.local.json`. It does not mean editing `agents/claude/settings.json`.
5. **Codex and OpenCode stay inactive.** Activation remains gated on the same portability bar per repository. The gate is not relaxed by this decision.
6. **Bootstrap resolves submodules before the final link/check.** `script/bootstrap` installs the base Git config first, synchronizes pinned submodules, then runs `script/link` / `script/check`. Managed agent symlinks would otherwise dangle on a fresh machine.

## Consequences

- Tool permissions (`defaultMode: bypassPermissions` plus `skipDangerousModePermissionPrompt`) come from the tracked submodule and survive a fresh machine without manual steps.
- The Herdr hook survives submodule updates because it never lived in the submodule.
- `script/link` gains symlink entries but no new dependency and no copying behavior; the public-directory composition root is unchanged.
- The dotfiles README no longer describes the Claude submodule as inactive.

## Re-evaluation triggers

Reconsider this decision if any of the following becomes true.

- `agents/claude` gains an officially supported portable mechanism for platform bindings, in which case decision 3 may be replaced rather than supplemented.
- A managed `~/.claude/settings.json` needs to be absent on some platform, which would break the assumption that one symlink is correct everywhere.
- Codex or OpenCode reaches the same portability bar and is activated; that activation reuses this mechanism rather than introducing a second one.
