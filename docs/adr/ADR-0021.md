# ADR-0021: Rex as a second agent execution runtime

- Status: Accepted
- Date: 2026-11-21
- Layer: Current practice / execution runtime, not Constitution
- Related: [#194](https://github.com/rebuildup/dotfiles/issues/194) (design), [#195](https://github.com/rebuildup/dotfiles/issues/195) (rex CLI wrapper), [#196](https://github.com/rebuildup/dotfiles/issues/196) (router selection), [#197](https://github.com/rebuildup/dotfiles/issues/197) (OMP status + skill), [#198](https://github.com/rebuildup/dotfiles/issues/198) (Mac verification), [#199](https://github.com/rebuildup/dotfiles/issues/199) (remote investigation)
- Extends: [ADR-0017](ADR-0017.md) (bounded continuity), [ADR-0019](ADR-0019.md) (router execution contract), [ADR-0020](ADR-0020.md) (credential handoff)
- Research: [docs/research/rex-integration-2026-11-21.md](../research/rex-integration-2026-11-21.md)

## Context

Rex (`rex 0.1.0-preview.21`, API revision 18) is a terminal multiplexer /
agent runtime: a server owns sessions, windows and terminal blocks; clients
(macOS app, iOS app, CLI, Lua scripts) attach to it. It is installed on the
Mac workstation and is the only Rex GUI environment today; Linux/FreeBSD
servers and a Windows server (testing, personal-server only) exist, and
remote access works over SSH (`rex -S ssh://user@host`) or Tailscale.

Herdr already fills the "optional Supervisor/session Practice" role for
`agent task` dispatch (ADR-0019 contract: classify once, keep the verdict,
run the authorized route). The operator wants Rex usable in parallel as a
second execution foundation — not as a Herdr replacement — so that Mac
daily work can move to Rex while Windows/WSL workers stay on Herdr until
Rex remote coverage justifies migration.

Rex's execution model differs from Herdr's in ways that matter:

- **No agent registry.** Herdr `agent start/list/prompt/wait/read` tracks
  named agents with `agent_status`. Rex tracks terminal *blocks*; an
  "agent" is just a process in a block. Worker identity must come from our
  own attempt records plus block labels, not from a runtime-side registry.
- **Different state signal.** Herdr reports `idle/working/blocked/done/
  unknown` per agent. Rex exposes the OSC 7501 *Program Status Protocol*:
  programs report `idle/working/done/blocked/error` (+`kind`, `msg`,
  `progress`) and the server exposes them via the
  `com.superlogical.terminal.program_status` block method and
  `terminal.program_status_changed` events. Adoption is per-program;
  OMP does not emit it today (a project-managed extension is added under
  #197, mirroring `herdr-omp-agent-state.ts`).
- **No `--env` on process creation.** `rex run`/`split`/`window new`
  inherit the *server's* environment, like Herdr. There is no equivalent
  of `herdr pane split --env`, so credential transport must reuse the
  ADR-0020 managed-profile resolution (secret stays inside Infisical and
  is fetched by the worker itself) — ambient credentials remain
  fail-closed on the task path.
- **Richer remote story.** `rex hosts` / `-S` give labelled remote
  servers over SSH/Tailscale; sessions survive client disconnects.

## Decision

### 1. rex-runtime is a Practice adapter, parallel to herdr-runtime

`rex-runtime` implements the same *logical* worker capabilities that
`herdr-runtime` does — create execution surface, start worker, observe,
prompt, read, wait, stop, recover — but is designed from Rex's model
(session → window → block), not by renaming Herdr concepts. Organizational
semantics (attempt class, authority, evidence, admission, recovery) stay
in project-init / Constitution / ADR-0019 and are unchanged.

### 2. Runtime selection is explicit; default is unchanged

`agent task run` accepts `--runtime herdr|rex`. The default remains
`herdr`, so existing invocations, fallback profiles and task state behave
exactly as before. `agent task resume`/`status`/`reconcile` operate on the
runtime recorded in the attempt — there is no silent cross-runtime
fallback or takeover. A task dispatched on one runtime is never resumed,
prompted or collected through the other; switching runtime means a new
dispatch (new attempt, normal fencing).

### 3. Canonical mapping

| Logical capability | Herdr | Rex |
| --- | --- | --- |
| execution surface | workspace | session (`rex new`) |
| function tab | tab | window (`rex window new`) |
| worker pane | pane | block (`rex run`/`split`, `--json` IDs) |
| worker identity | agent name (registry) | block label + attempt record |
| agent state | `agent_status` | OSC 7501 `program_status` records; degraded to `process`/`capture` when absent |
| send work | `agent prompt` | `rex send` + `rex send-key enter` into the block |
| read result | `agent read` | `rex capture --trim` (+ scrollback) |
| wait | `agent wait` | `rex wait --for` for process exit; status polling otherwise |
| teardown | `pane close` / workspace lifecycle | `rex block close` / `window close` / `kill` |

Block/window/session IDs returned by `--json` commands are the only
authoritative handles; labels and ID suffixes are convenience targets and
are never guessed.

### 4. State observation is evidence-tiered

Observation quality is reported, not assumed:

1. `program_status` records (OSC 7501) — authoritative `state`, `kind`,
   `msg` when the worker program emits them.
2. `process` block method — foreground process liveness and `last_exit`.
3. `capture` screen + `rex events` lifecycle — last resort.

A missing or `unknown` state is never treated as success, matching the
ADR-0019 contract. Until #197 lands, OMP workers on Rex report no OSC 7501
and observation degrades to tiers 2–3; acceptance criteria remain the
completion gate either way.

### 5. Credential policy is inherited unchanged (ADR-0020)

No secret value may appear in `rex` argv, the Rex server's state, logs, or
task state files. `rex run` has no `--env`, so only non-secret environment
(for example `OMP_SKIP_SETUP=1`) may be prefixed via `env NAME=VALUE`.
Managed-profile providers keep resolving credentials inside OMP through
`infisical-key.sh`; ambient-credential providers stay fail-closed on the
`agent task` path for **both** runtimes.

### 6. Ownership and fencing

An attempt's worker is owned by exactly one runtime, fixed at dispatch and
recorded in the attempt (`runtime` + runtime-scoped IDs). The existing
lease / journal / generation fencing in `attempts.ts`/`checkpoint.ts` is
runtime-agnostic and applies unchanged. Cleanup closes only the runtime
resources the attempt created; a live worker observed under the *other*
runtime is treated as foreign state and is never signalled.

### 7. Herdr interop is composition, not dependency

Inside a Rex terminal, `herdr` remains available on PATH, so an operator
or agent can drive Herdr sessions from Rex (and vice versa) using the
existing official CLIs. Neither runtime requires the other: the rex path
must work with Herdr stopped, and the herdr path must work with Rex
stopped. Windows/WSL workers continue on the Herdr path during the Mac
trial period.

### 8. Remote execution is a documented future path, not a requirement

`rex -S ssh://user@host` and `rex hosts` make a Linux Rex server usable as
an independent second route (see research memo). This ADR does not require
it: the initial scope is the local Mac server. Windows server support is
preview/personal-only and is not assumed.

### 9. Agent skill/hook policy

`rex skill setup` writes into global agent config dirs (`~/.claude`,
`~/.agents`, `~/.codex`). Per project policy, project-local Skills are
canonical and global installs are not a correctness prerequisite, so the
project ships `.agents/skills/rex-runtime` and does not require
`rex skill setup`. A user may still opt into the upstream skill/hooks on
their own machine; that choice is machine-local and outside this ADR.

## Consequences

- `agent task` gains an explicit runtime axis; all existing behavior is
  preserved under the default.
- Task state schema gains `runtime` + Rex-scoped refs; old Herdr records
  remain readable (fields stay optional/absent as today).
- OMP workers on Rex need the project-managed OSC 7501 extension (#197)
  for first-class status; without it the runtime still works at reduced
  observability.
- Remote Rex hosts become a cheap future extension of the same adapter
  (`-S` flag), but SSH/linger/Tailscale prerequisites must be verified
  per host before use (#199).

## Alternatives considered

- **Extend herdr.ts with Rex commands**: rejected — the models differ
  (registry vs blocks, `agent prompt` vs `send`+poll); a shared file
  would mix two contracts.
- **Rex-only migration, retire Herdr**: rejected by requirement — Herdr
  remains the multi-device path until Rex remote coverage is proven.
- **Headless `omp` invocation instead of a TUI block**: rejected for the
  task path — resume/observe semantics and the existing acceptance flow
  assume an interactive worker session; a future non-interactive mode is
  a separate design.
