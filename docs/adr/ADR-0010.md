# ADR-0010: Compose the effective Claude settings from the shared baseline and a machine-local overlay

- Status: Accepted (design); real-machine verification of the Herdr integration is pending, tracked in an Issue
- Date: 2026-10-17
- Classification: Architecture / Practice
- Extends: ADR-0005, ADR-0008
- Supersedes: the symlink activation proposed in ADR-0010 of 2026-10-07 (not merged)

## Context

ADR-0005 pins Claude Code global configuration as the `agents/claude` submodule and defers activation until that baseline is portable and provider-neutral (ADR-0008 decision 6).

Two problems block a direct symlink from `~/.claude/settings.json` to the submodule:

- The Herdr `SessionStart` hook is machine-specific and is written into the live file by Herdr. A symlink would send those writes into the submodule checkout.
- Claude Code has no user-scope local override. `.claude/settings.local.json` is project-scoped; a file under `~/.claude/` is not merged over the user settings.

The `statusLine` setting also lives in the submodule baseline, so the live file must carry the baseline content.

## Decision

1. **The live file is generated, never a symlink.** `~/.claude/settings.json` is the effective configuration: the shared baseline `agents/claude/settings.json` with a machine-local overlay merged on top. `script/claude-settings.ts compose` writes it; `check` reports drift without writing.
2. **Merge rules.** Objects merge key by key. Arrays append overlay items not already present, so hooks and permission lists add up. Scalars take the overlay value.
3. **Overlay location.** `${XDG_CONFIG_HOME:-~/.config}/dotfiles/claude/settings.local.json`. It is untracked and machine-local. Herdr's hook belongs here.
4. **Live-only values are imported, not discarded.** When the live file is not the last file the composer generated (checked by its SHA-256 record), anything it adds beyond the baseline is merged into the overlay first. A scalar that would silently change an existing overlay value aborts the run.
5. **No silent overwrite.** A replaced live file is copied to `settings.json.pre-dotfiles-<timestamp>` with an exclusive copy. Invalid JSON, a foreign symlink, or a directory at the target aborts with no change. An old symlink pointing at the shared baseline is replaced by the generated file; the baseline itself is never modified.
6. **Link stays pure.** `script/link` does not touch Claude settings. `script/bootstrap` resolves the submodule, asserts the shared baseline exists, links, composes, and only then runs `script/check`. If Bun is missing or the shared baseline is missing, bootstrap fails with a clear error before `script/check` runs; the composer CLI also exits non-zero on a skip result so direct invocation cannot silently succeed.
7. **Submodule not initialized is an error during bootstrap.** The composer function still returns skip when invoked without a baseline (useful for unit tests and for `script/check` in submodule-less trees); the bootstrap path requires the baseline to be present, and the `compose` CLI surfaces a skip result as exit 1 so direct invocation cannot silently succeed.
8. **Codex and OpenCode stay inactive.** Activation remains gated on the same portability bar.
9. **Bootstrap order is link → compose → check → secrets-doctor.** Composing before `script/check` is required: the freshly populated `~/.claude/settings.json` would otherwise appear as drift and bootstrap would terminate.
10. **`statusLine` and `model` are protected keys.** The composer never imports `statusLine` or `model` from the live file, the old-layout target, or a stale overlay into the new overlay. Tools that hook into Claude Code (Orca, Herdr, etc.) sometimes rewrite the live `statusLine` to inject their own progress notifications; `model` is a per-session choice, not a global setting, and a stale `model=haiku` pin from a pre-0.3.0 install must not survive migration. The canonical value for `statusLine` comes from the shared baseline; protected keys that were present in the overlay are reported in the action log so the operator can recover them if the canonical change was unintentional, and the overlay file is rewritten without them so the strip persists across runs.
11. **Pre-0.3.0 symlinks are auto-migrated.** A `~/.claude/settings.json` symlink that points at the old dotfiles layout (`<repo>/home/.claude/settings.json`) is recognised and replaced by a fresh composed regular file. The old-layout target's machine-local additions (e.g. Herdr or Orca hooks, but not protected keys) are merged into the overlay before the symlink is removed, so machine-specific values survive the migration. If the old-layout target still exists on disk, the composer copies it aside under `${XDG_CONFIG_HOME:-~/.config}/dotfiles/claude/legacy-<timestamp>/settings.json` before unlinking, so the file itself is preserved outside the managed dotfiles repository. A dangling symlink whose textual target was under the old layout is also replaced; a foreign symlink to anywhere else is left for the operator to handle.
12. **Backups live outside the managed repository.** Any backup the composer creates (the old-layout target, the live file before replacement) lands under the state directory (`${XDG_CONFIG_HOME:-~/.config}/dotfiles/claude/legacy-<timestamp>/`), not next to the live file and not inside the dotfiles repository. `script/link` and `script/check` skip the composer-owned `home/.claude/settings.json` so a stale working-tree copy is never re-symlinked, and `.gitignore` excludes any `*.bak` or `*.pre-dotfiles-*` artifacts that might appear in the repository.

## Consequences

- The baseline's tool permissions and `statusLine` reach the live file on a fresh machine without manual steps.
- Herdr writes into the live file are kept in the overlay on the next compose. They never reach the submodule.
- Each replaced live file leaves a backup under the state directory (outside the managed repository). Backups accumulate and are not cleaned up automatically.
- A key deleted from the live file is restored from the baseline on compose; deletions are not recorded.
- A tool that rewrites `statusLine` on the live file cannot orphan that rewrite into the overlay; the canonical render is always restored. A `statusLine` already present in the overlay is dropped on the next compose and reported in the action log.
- A pre-0.3.0 symlink at `~/.claude/settings.json` is migrated without operator action; the old-layout target file (if any) is backed up under the state directory before unlinking, and its machine-local additions (excluding protected keys) are merged into the overlay.
- A stale `model=haiku` pin (or any other `model` value) from a pre-0.3.0 install or a prior overlay never survives a compose.
- Unverified: the real Herdr write-back cycle and the statusLine rendering on each OS. These are tracked as Issues and are not claimed as verified here.

## Re-evaluation triggers

- `agents/claude` gains an officially supported platform-binding mechanism; the overlay may then be replaced.
- Claude Code gains a user-scope local override file; the overlay location should move to it.
- Codex or OpenCode reaches the same portability bar; they reuse this composer rather than a second mechanism.
