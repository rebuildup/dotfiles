# ADR-0007: Use the Infisical file vault on WSL

- Status: Accepted
- Date: 2026-09-23
- Extends: ADR-0004, ADR-0006
- Superseded by: None

## Context

The dotfiles bootstrap uses an Infisical user session against the self-hosted instance at `https://secrets.rebuildup.dev`.

Infisical's `auto` vault backend may use the Linux system keyring. That assumes a working Secret Service / D-Bus session. A WSL development environment is not required to provide that desktop keyring service, and an attempted keyring operation can block the bootstrap instead of failing quickly.

The first runtime secret fetch also creates or reads Infisical's local backup-encryption key, so a machine can appear to have a readable login session and still block later during `infisical run`.

## Decision

On WSL, `script/bootstrap` MUST configure Infisical's `file` vault backend before validating the user session.

This is intentionally WSL-specific. macOS, Windows native, and non-WSL Linux are not forced away from their normal keyring selection.

Changing Infisical vault backend invalidates the session stored in the previous backend. The bootstrap therefore treats re-authentication as an expected migration step and reuses its explicit self-host login flow.

`script/secrets-doctor` MUST:

1. validate the tracked self-host project/environment binding
2. validate the Infisical login session with `infisical login status --json`
3. validate actual project secret/runtime access with an `infisical run ... -- true` probe
4. bound external Infisical probes so bootstrap cannot wait indefinitely
5. preserve stderr on failure instead of suppressing the diagnostic

The probe timeout defaults to 20 seconds and may be overridden for testing with `DOTFILES_INFISICAL_PROBE_TIMEOUT_SECONDS`.

## Consequences

- WSL no longer depends on Secret Service / D-Bus for Infisical credential storage.
- The first bootstrap after this change may require one fresh Infisical login because switching vault backend deliberately clears the previous login state.
- Runtime access remains verified rather than being reduced to a structural config check.
- Infisical API or vault stalls fail with an explicit stage and timeout instead of appearing to freeze.
- The self-hosted instance remains mandatory; there is no fallback to Infisical Cloud.

## Re-evaluation triggers

Reconsider this decision if Infisical provides a WSL-safe auto backend with a bounded failure path, or if pc-setup makes a Linux Secret Service an explicit and verified machine dependency.
