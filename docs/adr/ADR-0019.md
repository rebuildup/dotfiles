# ADR-0019: OpenClaw Gateway as the resident Supervisor runtime

- Status: Accepted
- Date: 2026-11-17
- Classification: Project-local Operating Policy / Practice
- Extends: ADR-0004 (Infisical), ADR-0005 (agent config submodules), ADR-0018 (free provider routes)
- References: rebuildup/pc-setup#196/#197, rebuildup/dotfiles#160/#161/#162, rebuildup/project-init#172

## Context

A Windows 11 fixed host runs an always-on autonomous development Supervisor.
Requirements: unattended boot start, restart/communication-failure recovery,
GitHub-driven work selection, Worker dispatch through herdr/`agent`,
free-model-first routing with no silent paid fallback, declarative
(dotfiles-managed) configuration, Tailscale remote operation, and minimal
Supervisor privileges per project-init contracts.

Candidates evaluated: **OpenClaw** (openclaw/openclaw) and **OpenBot**.

## Decision

1. **OpenClaw is the Supervisor runtime.** It provides a single Gateway
   process with systemd user-service install on WSL2, persistent automations
   (cron/one-shot/webhook), SecretRef credential resolution, standing orders
   via workspace `AGENTS.md`, sub-agent/ACP delegation, and loopback binding
   with Tailscale-aware deployment docs. OpenBot did not offer an equivalent
   self-hosted scheduler + secrets + service-management surface for this
   role; OpenClaw's "trusted gateway, untrusted execution" model also matches
   the project-init Supervisor/Worker boundary.
2. **WSL2 (Ubuntu) is the Gateway execution environment** (pc-setup#196).
   Windows-native operation is limited to starting the WSL distro at logon
   and Tailscale exposure (pc-setup#197); no Windows-native OpenClaw install
   is required for the baseline.
3. **The Gateway runs under Infisical injection.** The systemd unit's
   ExecStart is wrapped by `script/with-secrets` via a drop-in override, so
   `gateway.auth.token` (SecretRef `env:OPENCLAW_GATEWAY_TOKEN`) and provider
   keys resolve without a human session. Provider API keys are **not** stored
   as OpenClaw auth profiles (plaintext residue); env injection is the only
   credential path (`openclaw secrets audit --check` must stay clean).
4. **Models are free-tier only.** `agents.defaults.model` and
   `modelPolicy.allow` in the managed `openclaw.json` enumerate explicit
   `:free` OpenRouter refs only; paid models are unreachable by policy.
   Quota exhaustion means wait/report, never silent paid failover.
5. **Declarative management lives in dotfiles.** `home/.openclaw/openclaw.json`
   and `home/.openclaw/workspace/AGENTS.md` are symlink-managed;
   `config/openclaw/automations/*.json` + `script/openclaw-automations`
   declare schedules; `script/openclaw-gateway-install` converges the service.
   Sessions, sqlite, logs, and workspace memory stay local state and are
   never committed.
6. **Supervisor authority follows project-init.** The standing orders
   reference project-init canonical documents for work selection, Worker
   dispatch (herdr/`agent`), recovery, quality gates, and release authority;
   the Supervisor does not implement code or merge `release -> main`.

## Consequences

- `openclaw gateway install` may rewrite the base unit on upgrades; the
  drop-in override must be re-applied by `script/openclaw-gateway-install`.
- OpenRouter `:free` quotas are small; fallbacks rotate within the allowlist
  and exhaustion surfaces as job failures, not billing.
- Adding a new provider requires: Infisical secret name, `modelPolicy.allow`
  entries, and an ADR-0018-consistent free-route evaluation.
