# ADR-0020: Credential handoff and executor state machine hardening

- Status: Accepted
- Date: 2026-11-18
- Layer: Current practice / agent routing, not Constitution
- Related: [#86](https://github.com/rebuildup/dotfiles/issues/86) (Epic), [#100](https://github.com/rebuildup/dotfiles/issues/100) (Herdr dispatch), [#167](https://github.com/rebuildup/dotfiles/issues/167) (OMP provider aggregation), [#168](https://github.com/rebuildup/dotfiles/pull/168) (omp_custom providers)
- Amends: [ADR-0019](ADR-0019.md) decisions 4 and 5 (candidate worker lifecycle, credential transport)
- Extends: [ADR-0017](ADR-0017.md) (bounded continuity), [ADR-0018](ADR-0018.md) (free-tier portfolio)

## Context

ADR-0019 fixed *what ran* and *why it failed* being misreported, but its
credential transport and several executor edges still had structural gaps:

1. **Secrets transited Herdr argv.** A Herdr worker inherits the *server's*
   environment, so the dispatcher passed the route credential as
   `herdr --env NAME=VALUE`. The value was visible in process arguments and
   persisted in the Herdr server — broader exposure than the
   `infisical run` process-scope the rest of the system uses.
2. **The worker path skipped launcher guards.** `planOmp` ran the
   destructive-guard/overlay/profile/credential-source checks, but a
   Herdr-started worker never went through `planOmp`: `buildAgentStartOptions`
   emitted a bare `--provider/--model` argv with no `--profile`, no tool
   overlay, and no managed-`models.yml` integrity check.
3. **A successful fallback worker was closed before collect.** The candidate
   pane was closed in a `finally` immediately after the prompt resolved, so
   `collectTaskAttempt` read a dead pane and lost the answer.
4. **Unknown failures could still advance.** A `taskFn` exception was
   swallowed into a synthetic `unknown` classification and the retry loop
   continued; `ContractError`s (config/credential defects) were likewise
   re-labelled. Zero usable candidates aborted the whole run even when the
   primary was healthy, and the executor recorded the route *default* model
   rather than the model the worker was actually pinned to.
5. **Attempt outcomes were not durable per candidate.** Only the final
   result was recorded; which route/model/credential scope ran, how each
   attempt failed, and which worker served it existed only in memory.

## Decision

### 1. Managed-profile credentials resolve inside OMP, never through Herdr

A provider needs a launcher-managed `models.yml` profile when it is
`omp_custom` (the file IS the provider definition) or a native provider
whose contract is `require_infisical` with a `secret` (the file overrides
only `apiKey`; OMP merges it with the built-in provider definition, so
provider id, base URL, model catalog and billing scope are unchanged).
Ambient-credential routes (`require_infisical = false`, e.g. openrouter,
deepseek, minimax) keep the env handoff — their contract is unchanged.

For a managed provider backed by an Infisical secret, the generated
`models.yml` declares

```yaml
apiKey: "!<repo>/script/agent/infisical-key.sh <SECRET_NAME>"
```

OMP executes the `!` command and uses trimmed stdout as the key (verified
against the installed OMP and a local HTTP stub that observed
`Authorization: Bearer <stdout>`). The secret travels Infisical → OMP
directly: it never enters Herdr `--env` argv, the pane environment, durable
task state, or the Herdr server. `script/agent/infisical-key.sh` pins the
self-hosted control plane (`https://secrets.rebuildup.dev`), the dotfiles
project id and the `dev` environment from `config/infisical.sh`; secret
*names* (never values) appear in `models.yml`.

`routeWorkerEnv` returns no credential for these providers, and
`verifyOmpManagedCredential` runs the helper once at dispatch (and per
candidate) so a missing Infisical session fails fast as `auth` instead of
surfacing as an opaque provider 401 inside the worker. This covers the
native Infisical routes (kilo, groq, opencode-go, mistral) as well as the
credentialed `omp_custom` routes (logfare, requesty, modelscope). The
env-name `apiKey` form remains only for ambient-credential providers;
anonymous providers keep `auth: "none"`.

### 2. One worker-argv builder for interactive and Herdr paths

`prepareOmpWorker(provider)` performs every side-effecting check the
launcher owns — managed `models.yml` generation/verification, ambient
`OMP_PROFILE`/`PI_*`/`OMP_*_DIR` rejection, implicit model-switch guard,
credential-source guard — and `ompWorkerArgs(provider, model, prepared)`
builds the argv: `--provider`, `--model`, `--profile` (managed-profile providers),
model-role pins, the destructive guard and tool-surface overlay via
`--trusted-extension`/`--config`, and the Herdr extension when inside
Herdr. `planOmp` (interactive) and `buildAgentStartOptions` (Herdr worker)
both delegate to them, so a Herdr worker gets exactly the hardening a
launcher-started OMP gets. `buildAgentStartOptions` refuses `omp_custom`
providers without a prior `prepareOmpWorker` and keeps the anonymous-provider
fail-closed check as defense in depth.

### 3. Managed `models.yml` is marker-owned, not hash-frozen

The generated file carries a `# Managed by the dotfiles agent launcher`
marker. A file *without* the marker is never touched (user-owned; could
redirect credential or endpoint). A stale file *with* the marker is the
launcher's own artifact from an older config/launcher version and is
rewritten atomically (`tmp` + `rename`), so an upgrade (env-name `apiKey` →
`!command`) does not wedge every route. The sha256 is still pinned at plan
time and rechecked before spawn.

### 4. Executor semantics: fail closed, record everything

`executeWithFallback` gains `FallbackExecutionOptions`:

- `primaryModel`: the model the task was dispatched with (validated against
  the route/provider allowlist, `ContractError("identity")` otherwise). The
  executor runs and records THAT model, not the route default.
- `onAttempt(record)`: invoked after EVERY attempt outcome — success or
  failure, primary or candidate — before the executor decides to retry,
  advance, or throw. `task.ts` persists each record into task history with
  route, model, credential *scope* (env/secret name, never a value),
  classified failure, generation, and serving worker/pane ids.

Failure handling is now explicit:

- `ContractError` from `taskFn` propagates unchanged — it is a launcher or
  config defect, not provider evidence, and must not be retried or
  re-labelled.
- Any other exception is recorded as `unknown` and stops the run via
  `FallbackExhaustedError` — advancing on unknown facts could silently
  change account/model/billing scope (ADR-0017).
- A classified `unknown` *signal* likewise stops after one attempt (already
  covered by ADR-0019's contract; unchanged).
- Zero usable candidates no longer aborts the run: fallback is authorized,
  not required, so a healthy primary executes normally.

The classifier itself is deduplicated: `fallback-exec.ts` re-exports the
canonical `limits.ts` taxonomy (`classifyFailure`, `CATEGORY_FACTS`,
`CATEGORY_SEVERITY`, `LIMIT_CATEGORIES`) and adapts only its own
`quotaScopeKey` provenance field. The two copies could previously drift;
there is now one owner.

### 5. Candidate pane lifecycle

A candidate worker's pane stays open while its result is read and is closed
only after `collectTaskAttempt` has consumed the serving worker's output —
or immediately when the candidate fails. The primary's root pane is never
closed by the router. `runTaskToCompletion` closes a successful candidate's
pane after collect; cleanup failures never mask the task outcome.

## Consequences

- Provider credentials for managed-profile routes (all `omp_custom` and
  every `require_infisical` native OMP provider) never appear in Herdr
  argv,
  pane environments, the Herdr server, logs, or durable state — only secret
  *names* do.
- A Herdr worker is guarded identically to an interactive launch: same
  profile, overlay, model pins, and credential-source checks.
- An `unknown` or defective failure can no longer advance candidates or be
  retried into a different account/model/billing scope.
- Every attempt is durably recorded per route/model/credential scope, so a
  resumed or audited task shows exactly what ran and why it failed.
- `limits.ts` is the single classification owner; `fallback-exec.ts` adds
  only the quota-scope provenance field.

## Verification

- `bun test script/` — 890 tests, 0 failures. New coverage:
  `FallbackExhaustedError` propagation of `ContractError`, fail-closed
  `unknown` on unexpected exceptions, `primaryModel` honored and
  allowlist-validated, `onAttempt` records for every attempt;
  `buildAgentStartOptions` requires `prepareOmpWorker` for managed-profile
  providers and emits the full hardened argv; managed-`models.yml`
  marker/stale-rewrite behavior; `apiKey` rendered as the `!command` form
  for both custom definitions and native apiKey overrides;
  `routeWorkerEnv` returns `{}` for native `require_infisical` providers
  even with the env var present; guard tests plant overrides in the
  profile agent dir OMP actually reads under `--profile`.
- Controlled credential-path probes (2026-11-18): a temporary OMP profile
  with `apiKey: "!fake-key.sh"` against a local HTTP stub received
  `Authorization: Bearer <command stdout>` — OMP executes the command and
  sends its output as the key; the same probe against the NATIVE `groq`
  provider id confirmed the models.yml apiKey override reaches the wire.
  `infisical-key.sh LOGFARE_API_KEY` resolves live against the
  self-hosted instance. `omp --profile dotfiles-omp-<key> models` lists
  the full built-in catalog for groq/kilo/mistral/opencode-go, proving the
  apiKey-only override merges without disturbing provider identity.
- Test-isolation fix: `agent.limits.test.ts`'s persistent `node:fs` module
  mock dropped `writeFileSync` options, stripping `0o755` from
  `devices.test.ts` stubs so `execvp` fell through to real binaries; the
  mock now forwards all arguments and the devices stubs chmod explicitly.
- Not verified here (RC scope): real-provider response/tool-call on the
  four `omp_custom` routes, 429-driven fallback, auth/billing boundaries,
  and end-to-end task continuation with artifact checks.
