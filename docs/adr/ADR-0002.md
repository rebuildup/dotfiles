# ADR-0002: Minimal common-first configuration and pc-setup boundary

- Status: Accepted
- Date: 2026-09-23
- Classification: Project-local Operating Policy
- Superseded by: None

## Context

Personal dotfiles tend to grow into a mixture of preferences, software installation, OS defaults, machine-specific values, copied snippets, and historical aliases. That makes a new machine harder to reason about and creates overlap with `rebuildup/pc-setup`.

This repository is intended to represent deliberate CLI preferences rather than a catalog of every possible tweak.

## Decision

1. `dotfiles` owns user-level configuration consumed by CLI tools and shells.
2. `pc-setup` owns software/package installation, OS defaults, package-manager configuration, and machine provisioning.
3. The common configuration is the default. Platform- or host-specific structure is added only when a real difference cannot be expressed cleanly by the tool itself.
4. Secrets, credentials, private keys, access tokens, and machine-specific identity values are not committed.
5. When a tool supports local includes or override files, machine-specific values should use that native boundary. The initial Git configuration therefore includes optional `~/.gitconfig.local`.
6. New configuration must solve an observed preference, incompatibility, or repeated manual action. Popularity in another person's dotfiles is not by itself a reason to add it.
7. Helper scripts and abstractions should stay proportional to the configuration they manage.

## Consequences

- The repository starts intentionally sparse.
- Reproducing a machine requires both this repository and `pc-setup`, with non-overlapping responsibilities.
- Some local files are intentionally not reproducible from Git because they contain identity, secrets, or host-specific state.
- Platform-specific directories may appear later, but empty speculative structure is avoided.

## Re-evaluation triggers

Revisit this decision if the boundary causes repeated duplication between `dotfiles` and `pc-setup`, or if multiple machines require the same currently-local data and a safe reproducible representation becomes available.
